# Яндекс SmartCaptcha для WordPress

Версия: **1.1.6**

Репозиторий: https://github.com/ar7iom/ysc-smartcaptcha

Плагин добавляет невидимую Yandex SmartCaptcha к поддерживаемым формам WordPress
и проверяет одноразовый токен на сервере. Задание показывается только тем
пользователям, которых сервис считает подозрительными.

## Поддерживаемые формы

- **Contact Form 7:** `form.wpcf7-form`, серверный фильтр `wpcf7_validate`.
- **Impreza / UpSolution:** формы `w-form`, `us-form`, `for_cform`, фильтр
  `us_form_validate` и AJAX-действия `us_ajax_form_submit`, `us_ajax_cform`.
- **WooCommerce:** классическое оформление заказа, вход и регистрация.
- **WordPress:** стандартная форма входа `wp-login.php`; XML-RPC исключён.

Каждый тип форм можно отдельно включить или отключить в настройках. WooCommerce
Checkout Blocks и Store API не поддерживаются. Совместимость с конкретной
версией WordPress, WooCommerce и Impreza следует проверять на своём стенде.

## Установка и обновление

1. Сделайте резервную копию сайта и текущей версии плагина.
2. Откройте «Плагины → Добавить новый → Загрузить плагин».
3. Загрузите архив `ysc-smartcaptcha-1-1-6.zip` и подтвердите замену.
4. Убедитесь, что в списке плагинов указана версия **1.1.6**.
5. Очистите кеш страниц, JavaScript-объединителя и CDN.
6. Откройте «Настройки → SmartCaptcha», проверьте ключи, лимит и типы форм.
7. Проверьте каждую используемую форму: успешную отправку, неверную капчу,
   повторную попытку после сетевой ошибки и отправку без токена.

Требуется **PHP 7.4+** и OpenSSL с поддержкой **AES-256-GCM** для сохранения
новых ключей. Для работы плагина нужны исходящие HTTPS-запросы с сервера к
`smartcaptcha.cloud.yandex.ru`.

## Настройка ключей

1. Создайте капчу в Yandex Cloud: https://console.yandex.cloud/ .
2. Разрешите домен сайта в настройках капчи.
3. Скопируйте клиентский и серверный ключи в «Настройки → SmartCaptcha».
4. Сохраните настройки и проверите форму в браузере.

Клиентский ключ передаётся в браузер. Серверный ключ используется только в
серверном запросе валидации и не добавляется в HTML или JavaScript. Если поле
ключа оставить пустым, сохраняется прежнее значение.

Новые значения шифруются **AES-256-GCM** с аутентификацией шифротекста. Ключ
шифрования производится от `AUTH_KEY` и специфической соли плагина. Старые
значения AES-256-CBC и унаследованный Base64 читаются для обратной совместимости;
новое сохранение без OpenSSL в формате Base64 больше не выполняется. Чтобы
перевести старый ключ на GCM, введите его повторно и сохраните настройки.

При смене `AUTH_KEY` ранее сохранённые ключи могут перестать расшифровываться —
в этом случае введите их заново. Резервная копия базы данных и `wp-config.php`
должны храниться с одинаковым уровнем доступа: шифрование не защищает ключи,
если атакующий получил и базу, и секреты WordPress.

## Уведомление об обработке данных

По умолчанию отображается стандартное уведомление SmartCaptcha. В настройках
есть отдельный чекбокс «Скрыть стандартное уведомление об обработке данных».

Включайте его только если на сайте уже размещено или будет вручную размещено
заметное официальное уведомление об обработке данных SmartCaptcha, например в
футере. Скрытие стандартного блока без альтернативного уведомления нарушает
требования сервиса. Официальное описание:
https://yandex.cloud/ru/docs/smartcaptcha/concepts/invisible-captcha

## Лимит запросов и уведомления

Локальный лимит по умолчанию — **10 000 запросов в месяц**. Его можно изменить
в настройках. Это внутренний счётчик плагина для контроля расходов, а не
синхронизация с биллингом Yandex Cloud.

Поведение при исчерпании лимита сохранено намеренно:

- новые серверные обращения к API валидации прекращаются;
- серверная проверка пропускается;
- скрипт капчи не подключается на вновь загружаемых страницах;
- формы продолжают работать без защиты до сброса счётчика или увеличения лимита.

Таким образом, плагин не начинает самостоятельно расходовать платные запросы.
Владелец сайта должен сам увеличить лимит, если разрешает продолжить проверки.

На порогах **80%** и **100%** администратору отправляется письмо через `wp_mail`.
Счётчик сбрасывается при первом обращении в новом месяце. При параллельных
запросах, сбоях базы данных или использовании тех же ключей другими приложениями
локальное значение может отличаться от фактического расхода в Yandex Cloud.

Для ручного сброса в режиме `WP_DEBUG` предусмотрена кнопка в настройках. Она
доступна только пользователю с правом `manage_options` и защищена nonce.

## Как работает проверка

1. До загрузки скрипта провайдера плагин регистрирует callback
   `yscSmartCaptchaOnload`.
2. Создаётся один общий невидимый виджет. Динамически добавленные формы
   обнаруживаются через `MutationObserver` и события интеграций.
3. При отправке формы стандартная обработка временно останавливается и вызывается
   `smartCaptcha.execute(widgetId)`.
4. После получения токена повторно запускается нативное событие `submit`, чтобы
   обработчики CF7, Impreza и WooCommerce сериализовали форму обычным способом.
5. PHP отправляет `secret`, `token` и валидный IP посетителя методом POST на
   `https://smartcaptcha.cloud.yandex.ru/validate`.
6. До исчерпания локального лимита запрос считается успешным только при HTTP 200
   и JSON-ответе со `status: "ok"`. Сетевые ошибки, HTTP-ошибки и невалидный JSON
   отклоняются.

Токен SmartCaptcha действует пять минут и предназначен для одной проверки. В
пределах одного PHP-запроса результат кешируется отдельно для каждого токена,
чтобы несколько хуков одной формы не расходовали его повторно. Между HTTP-запросами
кеш не сохраняется.

Повторный клик не запускает параллельную проверку. При сетевой или JavaScript-ошибке
форма не отправляется без токена, пользователю выводится сообщение и доступна
повторная попытка. Ожидание ответа виджета ограничено 120 секундами.

Официальная документация:

- https://yandex.cloud/ru/docs/smartcaptcha/
- https://yandex.cloud/ru/docs/smartcaptcha/concepts/widget-methods
- https://yandex.cloud/ru/docs/smartcaptcha/operations/validate-captcha

## Изменения в версии 1.1.6

- Реализация сверена с актуальной документацией Yandex SmartCaptcha.
- Адреса скрипта и серверной валидации переведены на
  `smartcaptcha.cloud.yandex.ru`.
- Добавлена настройка скрытия стандартного уведомления; по умолчанию оно показывается.
- Новые ключи шифруются AES-256-GCM в версионированном формате `ysc2:`.
- Сохранено чтение старых AES-256-CBC и Base64-значений.
- Убрано сохранение новых ключей в незашифрованном Base64 при отсутствии OpenSSL.
- При ошибке шифрования прежний ключ больше не заменяется пустой строкой.
- Улучшена защита от повторного шифрования при повторной санитизации WordPress.
- Токен и `REMOTE_ADDR` обрабатываются только как строки; IP проверяется через
  `filter_var`, массивы и невалидные значения безопасно отклоняются.
- При ошибке капчи входа WooCommerce сохраняются уже существующие ошибки `WP_Error`.
- Улучшено добавление класса `ysc-protected`: учитываются регистр HTML-атрибутов,
  пробелы вокруг `=`, нестроковые AJAX/HTML-данные не передаются в регулярные выражения.
- Убран повторный вызов чтения HTTP-кода ответа.
- Добавлены автономные PHP- и JavaScript-тесты. Поведение лимита и уведомлений
  специально проверено и не изменено.

## Диагностика

1. Проверьте, что клиентский и серверный ключи принадлежат одной капче, а домен
   сайта разрешён в Yandex Cloud.
2. В Network браузера проверьте загрузку
   `https://smartcaptcha.cloud.yandex.ru/captcha.js` и запросы виджета.
3. Запрос `/validate` выполняет PHP-сервер, поэтому в Network браузера его нет.
4. Проверьте исходящие HTTPS-соединения сервера, DNS, брандмауэр и PHP error log.
5. Повторите проблему без браузерных расширений и с временно отключённым
   JavaScript-объединителем или оптимизатором.
6. На тестовом сайте отправьте форму без `smart-token`: до исчерпания лимита
   сервер должен отклонить её. После исчерпания лимита действует описанный выше
   намеренный обход проверки.
7. Не публикуйте серверный ключ, полные токены и персональные данные посетителей.

Ошибки React, Метрики, CORS на ресурсах Яндекса или Encrypted Media Extensions
не следует диагностировать только по скриншоту консоли: нужны полный адрес
ресурса, стек и воспроизводимый сценарий.

## Автоматические проверки

В репозитории находятся автономные тесты без полной установки WordPress:

```bash
php -d extension=openssl tests/php/run.php
node --check assets/frontend.js
node tests/js/run.cjs
```

Для версии 1.1.6 успешно выполнены:

- синтаксическая проверка всех PHP-файлов на PHP 8.3;
- синтаксическая проверка `assets/frontend.js` на Node.js 24;
- **13 PHP-тестов**: GCM, CBC/Base64-совместимость, настройки, входные данные,
  API, кеш токена, поведение лимита, WooCommerce, HTML и подключение скрипта;
- **8 JavaScript-тестов**: единичный render, настройка уведомления, submitter,
  токен во время submit, повторные клики, конкурирующие формы, сетевые и
  JavaScript-ошибки, `challenge-hidden`, недоступный провайдер.

Тесты используют имитацию WordPress и SmartCaptcha. Проверка с реальными ключами,
боевой темой Impreza и полной установкой WordPress/WooCommerce в локальном
окружении не выполнялась; перед обновлением рабочего сайта рекомендуется стендовая
проверка.
