# Яндекс SmartCaptcha для WordPress

Версия сборки: **1.1.5**. Основа: код версии 1.1.4 из
https://github.com/ar7iom/ysc-smartcaptcha.

Плагин подключает невидимую SmartCaptcha и проверяет полученный токен
на сервере. При необходимости сервис может показать пользователю задание.

## Изменения 1.1.5

- JavaScript вынесен в assets/frontend.js; конфигурация передаётся через JSON.
- Один общий экземпляр виджета и защита от повторной инициализации скрипта.
- Повторный клик не запускает вторую проверку; другая форма не перехватывает
  результат уже начатой проверки.
- Сохраняется кнопка отправки при requestSubmit; используется нативное событие
  submit, доступное обработчикам форм.
- Виджет сбрасывается перед новой проверкой, а не перед сериализацией формы.
- Добавлены обработчики network-error, javascript-error, token-expired и
  challenge-hidden. При ошибке выводится сообщение рядом с формой.
- Ожидание ограничено 120 секундами. При недоступности провайдера форма
  не отправляется без проверки, пользователь может повторить попытку.
- Убран неподтверждённый параметр robustness: 'auto': он не исправляет
  предупреждения браузерного API Encrypted Media Extensions.
- Убраны скрытие iframe и принудительное позиционирование контейнеров капчи
  из CSS плагина. Отображением задания управляет SmartCaptcha.
- Убрана подписка на каждый jQuery AJAX-запрос; динамические формы обнаруживает
  MutationObserver и события интеграций.
- Добавлена серверная проверка действия Impreza us_ajax_cform для гостей и
  авторизованных пользователей. Старые обработчики оставлены для совместимости.
- Добавлена серверная проверка регистрации WooCommerce.
- Результат серверной проверки кешируется отдельно для каждого токена;
  успешная проверка одного токена не разрешает другой токен в том же запросе.
- Для успеха API необходимы HTTP 200 и status=ok; пустой, слишком длинный
  или некорректный токен отклоняется. Серверные ключи не пишутся в логи.
- Исправлено повторное шифрование при повторной санитизации WordPress
  в рамках одного сохранения. Формат существующих зашифрованных ключей сохранён.

## Установка и обновление

1. Сохраните резервную копию текущей версии.
2. В WordPress откройте «Плагины → Добавить новый → Загрузить плагин».
3. Выберите ysc-smartcaptcha-1-1-5.zip и подтвердите замену версии.
4. Убедитесь, что в списке плагинов указана версия 1.1.5.
5. Очистите кеш страниц, объединения JavaScript и CDN.
6. Откройте «Настройки → SmartCaptcha», проверьте ключи и включённые формы.
7. Проверьте отправку каждой используемой формы и повторную отправку после ошибки.

Используйте PHP 7.4+ с OpenSSL. Поддержку конкретных версий WordPress, темы
и плагинов форм необходимо проверять на вашем стенде. Плагин использует
классические формы WooCommerce; Checkout Blocks и Store API не охвачены.

## Ключи

Получите клиентский и серверный ключи одной капчи в Яндекс Cloud:
https://console.yandex.cloud/ . Разрешите домен сайта в настройках сервиса.
Клиентский ключ передаётся в браузер. Серверный ключ остаётся на сервере.
Пустое поле в настройках сохраняет прежний ключ.

Ключи в базе шифруются AES-256-CBC с производным от AUTH_KEY ключом.
При смене AUTH_KEY может потребоваться повторный ввод ключей.
Существующий формат CBC не содержит проверки подлинности шифротекста.
В унаследованной реализации при отсутствии OpenSSL используется Base64 —
это кодирование, а не шифрование. Используйте OpenSSL.

## Формы и ограничения

- Contact Form 7: клиентское перехватывание и существующий фильтр валидации.
- Impreza / UpSolution: формы w-form, us-form, for_cform; серверные действия
  us_ajax_cform и us_ajax_form_submit, существующий фильтр us_form_validate.
- WooCommerce: классическое оформление заказа, вход и регистрация.
- WordPress: стандартная форма входа; XML-RPC исключён из проверки.

Работа с конкретной версией темы требует проверки фактического AJAX-запроса.
Добавление капчи в интерфейс само по себе не доказывает серверную защиту.

## Лимит запросов

По умолчанию настроен локальный лимит 10 000 запросов в месяц.
Это настройка плагина, а не гарантия действующего тарифа Яндекса.
Счётчик не синхронизирован с биллингом и может расходиться с ним при
параллельных запросах или использовании ключей другими приложениями.

Сохранено прежнее поведение: при достижении лимита серверная проверка
пропускается, а скрипт не подключается на новых страницах. Формы продолжают
работать без защиты. Счётчик сбрасывается при первом обращении в новом месяце.
Письма о порогах 80% и 100% отправляются администратору через wp_mail.

## Ошибки из консоли браузера

| Сообщение | Что означает и что сделано |
| --- | --- |
| React #418 / #423 | Ошибки гидратации и перехода на клиентский рендеринг. По скриншоту нельзя установить первопричину. В плагине исключены повторные render и скрытие контейнеров, но ошибки внутри провайдера могут остаться. |
| Permissions policy: unload is not allowed | Один из скриптов обращается к ограниченному браузером API. По сокращённому main.js?attr нельзя надёжно назвать источник; нужен полный адрес и стек. Плагин unload не использует. |
| mc.yandex.ru, ERR_ABORTED 499 | Сбой или блокировка загрузки Метрики. Это не ответ серверной валидации SmartCaptcha. Проверяйте сеть, расширения и защитное ПО. |
| CORS от origin https://yandex.ru к yastatic.net | Ошибка в документе или фрейме Яндекса. Заголовки WordPress не меняют ответы yastatic.net. Возможны сетевые фильтры и модификация ответов; причина по скриншоту не установлена. |
| robustness level | Предупреждение может относиться к Encrypted Media Extensions. Не следует лечить его произвольным параметром smartCaptcha.render. |

Плагин не отключает браузерную безопасность, не меняет CORS чужих ресурсов,
не удаляет Метрику и не подавляет console.error.

## Диагностика

1. Повторите проблему в чистом профиле браузера без расширений.
2. Сравните с другим браузером и сетью. Ограничения антивируса и прокси
   могут действовать даже в режиме инкогнито.
3. В Network проверьте загрузку captcha.js, запросы виджета и AJAX формы.
4. Запрос /validate выполняет PHP-сервер: в Network браузера его обычно нет.
5. Для серверных ошибок проверьте PHP error log или настроенный debug.log.
   Не публикуйте серверные ключи, полные токены и данные посетителей.
6. Для проверки защиты на тестовом сайте отправьте форму без smart-token:
   сервер должен её отклонить, пока локальный лимит не исчерпан.

## Проверки сборки

Проверен синтаксис всех PHP-файлов и frontend.js. Локальные тесты с имитацией
SmartCaptcha проверяют единичный render, повторный клик, конкурирующие формы,
сохранение submitter и токена во время submit, восстановление после network-error.
PHP-тесты проверяют шифрование/расшифровку, повторную санитизацию и кеш проверки
по токенам. Тесты с реальными ключами и установленной темой на боевом сайте
в рамках подготовки архива не выполнялись.
