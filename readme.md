# 🛡️ Яндекс SmartCaptcha для WordPress

**Версия:** 1.1.3  
**Требования:** WordPress 5.0+, PHP 7.4+, OpenSSL  
**Лицензия:** GPL-2.0-or-later

Плагин добавляет **невидимую** Яндекс SmartCaptcha ко всем формам на сайте. Пользователь не видит капчу — она работает в фоне и запускает проверку только при подозрительном поведении. Поддерживает Contact Form 7, Impreza / UpSolution, WooCommerce и стандартную форму входа WordPress.

## Возможности

- **Невидимая капча** — не требует действий от пользователя, не раздражает
- **Поддержка популярных плагинов** — CF7, Impreza, WooCommerce, wp-login.php
- **Динамические JS-селекторы** — в браузер попадают только те селекторы, которые включены в настройках
- **Серверная валидация** — каждый токен проверяется через API Яндекса
- **Шифрование ключей API** — хранятся в БД в зашифрованном виде (AES-256-CBC)
- **Счётчик запросов** — встроенный учёт с автосбросом каждый месяц
- **Email-уведомления** — предупреждения при 80% и 100% лимита
- **Виджет на дашборде** — быстрый обзор статуса прямо в админке
- **Страница настроек** — управление ключами и типами форм без правки кода
- **Автоотключение** — при исчерпании лимита проверка отключается, формы продолжают работать

## Как это работает

```
Пользователь заполняет форму
        │
        ▼
Нажимает «Отправить»
        │
        ▼
JS перехватывает событие submit
        │
        ▼
SmartCaptcha выполняет невидимую проверку (fingerprint, поведение)
        │
        ├─► Подозрительный → показывает визуальную капчу
        │
        └─► Обычный пользователь → получает токен автоматически
                    │
                    ▼
        Токен записывается в <input type="hidden" name="smart-token">
                    │
                    ▼
        Форма отправляется (submit продолжается)
                    │
                    ▼
        PHP отправляет токен на сервер Яндекса для проверки
                    │
                    ├─► status: ok  → форма обрабатывается
                    └─► status: failed → форма отклоняется с ошибкой
```

## Установка

### Способ 1 — Через админку WordPress (рекомендуется)

1. Скачайте архив `ysc-smartcaptcha-1-1-3.zip`
2. В админке: **Плагины → Добавить новый → Загрузить плагин**
3. Выберите архив, нажмите **«Установить сейчас»**
4. Нажмите **«Активировать плагин»**

### Способ 2 — Через FTP / файловый менеджер

1. Распакуйте архив `ysc-smartcaptcha-1-1-3.zip`
2. Загрузите папку `ysc-smartcaptcha` в `/wp-content/plugins/`
3. В админке: **Плагины → Установленные**
4. Найдите «Яндекс SmartCaptcha», нажмите **«Активировать»**

## Настройка

### Шаг 1 — Получить ключи в Яндекс Cloud

1. Откройте [console.yandex.cloud](https://console.yandex.cloud/)
2. Перейдите в раздел **SmartCaptcha**
3. Создайте новый каптча-сервис или откройте существующий
4. Скопируйте **Клиентский ключ** (публичный, начинается с `ysc1_...`)
5. Скопируйте **Серверный ключ** (секретный, начинается с `ysc2_...`)

> Важно: домен сайта в настройках каптчи в Яндекс Cloud должен совпадать с реальным доменом сайта.

### Шаг 2 — Ввести ключи в плагине

1. В админке: **Настройки → SmartCaptcha**
2. Вставьте **Клиентский ключ** — виден на фронтенде, передаётся в JS
3. Вставьте **Серверный ключ** — используется только на сервере, в браузер не попадает
4. Нажмите **«Сохранить настройки»**

После сохранения оба поля показывают `••••••••••••••••••••` — это нормально,
ключи зашифрованы. Поле с пустым значением при сохранении оставляет текущий ключ без изменений.

### Шаг 3 — Выбрать типы форм

В разделе **«Защищаемые типы форм»** включите только то, что реально используется на сайте:

| Тип                  | Включать если...                              |
|----------------------|-----------------------------------------------|
| Contact Form 7       | Установлен плагин CF7                         |
| Impreza / UpSolution | Используется тема Impreza                     |
| WooCommerce          | Установлен WooCommerce                        |
| WordPress Login      | Всегда — защищает стандартную форму входа     |

Отключение неиспользуемых типов убирает лишние PHP-хуки и JS-селекторы.

## Поддерживаемые формы

### Contact Form 7

Капча добавляется ко всем формам CF7. Валидация через фильтр `wpcf7_validate` —
при невалидном токене форма возвращает ошибку пользователю.

**Селекторы JS:** `form.wpcf7-form`, `.wpcf7 form`

**События CF7:** `wpcf7mailsent`, `wpcf7invalid`, `wpcf7spam`, `wpcf7mailfailed`, `wpcf7submit` —
при каждом из них форма повторно сканируется и переинициализируется.

### Impreza / UpSolution

Полная поддержка форм темы Impreza, включая AJAX-формы, попапы и динамические сетки.

- Добавляет класс через фильтр `us_form_args`
- Обрабатывает AJAX-ответы через `us_ajax_response`
- Буферизует вывод `us_ajax_grid` для патчинга форм в динамическом контенте
- События: `us_init`, `us_grid_loaded`, `us_popup_open`

**Селекторы JS:** `form.w-form`, `form.us-form`, `.wpb_content_element form`,
`.vc_column-inner form`, `.us-grid form`, `.reusable-block form`, `[data-us-block] form`

### WooCommerce

- **Оформление заказа** — хук `woocommerce_checkout_process`
- **Вход через WooCommerce** — хук `woocommerce_process_login_errors`
- **Регистрация** — CSS-селектор `form.woocommerce-form-register`

### WordPress Login (wp-login.php)

Защита стандартной формы входа через фильтр `authenticate` (приоритет 30).
XML-RPC запросы автоматически пропускаются без проверки капчи.

**Селектор JS:** `#loginform`

## Безопасность

### Шифрование ключей API

| Параметр           | Значение                                           |
|--------------------|----------------------------------------------------|
| Алгоритм           | AES-256-CBC                                        |
| Ключ шифрования    | `hex2bin(SHA-256(AUTH_KEY + 'ysc_v1'))` — 32 байта |
| Вектор (IV)        | Случайный 16 байт, `openssl_random_pseudo_bytes`   |
| Формат в БД        | `base64(IV + зашифрованные_данные)`                |

Даже при компрометации базы данных ключи нельзя восстановить без `AUTH_KEY`
из `wp-config.php`.

> ⚠️ **При переносе сайта** на сервер с другим `AUTH_KEY` потребуется заново
> ввести ключи API в **Настройки → SmartCaptcha**.

### Серверная валидация

Каждая отправка формы проходит проверку:

```
POST https://smartcaptcha.yandexcloud.net/validate
  secret = <серверный ключ>
  token  = <smart-token из POST>
  ip     = <IP пользователя>
```

Серверный ключ используется только для запросов с сервера к API Яндекса.
В браузер он никогда не передаётся.

### Однократная проверка токена

`ysc_verify_token()` использует статический кэш — в рамках одного HTTP-запроса
токен проверяется ровно один раз, даже если форма обрабатывается несколькими хуками.

### Санитизация входных данных

Все данные из `$_POST` и `$_GET` обрабатываются через `sanitize_text_field()`
и `wp_unslash()` перед использованием.

## Счётчик запросов и лимиты

Бесплатный тариф Яндекс SmartCaptcha — **10 000 проверок в месяц**.
Плагин ведёт собственный счётчик в `wp_options`.

### Как работает счётчик

- Инкрементируется при каждой серверной проверке токена
- Автоматически сбрасывается в начале каждого календарного месяца
- Использует статическое кэширование для минимизации запросов к БД
- Параметр `$reset_cache` позволяет сбросить кэш после инкремента

### Поведение при исчерпании лимита

При достижении `count >= YSC_MONTHLY_LIMIT`:

- Скрипт SmartCaptcha перестаёт загружаться на фронтенде
- Серверная валидация пропускается и возвращает `true` (формы работают)
- В лог PHP пишется `[YSC] Лимит исчерпан`
- На дашборде отображается статус **⛔ Лимит исчерпан**

### Изменение лимита

Значение настраивается в поле **«Лимит запросов / месяц»**.
При переходе на платный тариф Яндекса — увеличьте значение соответственно.

## Email-уведомления

| Триггер               | Тема письма                                               |
|-----------------------|-----------------------------------------------------------|
| Использовано ≥ 80%    | `[Сайт] Яндекс SmartCaptcha: использовано 80% лимита`    |
| Лимит исчерпан (100%) | `[Сайт] Лимит Яндекс SmartCaptcha исчерпан`              |

Каждое уведомление отправляется **один раз в месяц** — повторные не отправляются.
Адрес получателя: **Настройки → Общие → Адрес электронной почты администратора**.

## Часто задаваемые вопросы

**Капча не появляется на форме. Что делать?**

Проверьте:
1. Клиентский ключ введён в **Настройки → SmartCaptcha** и помечен ✓
2. Домен сайта совпадает с доменом в кабинете Яндекс Cloud
3. Тип формы включён в чекбоксах настроек
4. В консоли браузера нет ошибок загрузки `smartcaptcha.yandexcloud.net`

---

**Форма отправляется, но выдаёт ошибку «Проверка капчи не пройдена».**

Проверьте:
1. Серверный ключ введён правильно (не перепутан с клиентским)
2. Сервер имеет доступ в интернет для запросов к `smartcaptcha.yandexcloud.net`
3. Логи PHP: `grep "\[YSC\]" /path/to/error.log`

---

**Счётчик показывает неверное число.**

Счётчик считает серверные проверки (запросы к API Яндекса), а не показы формы.
Одна отправка формы = один запрос = +1 к счётчику.
В режиме `WP_DEBUG` на странице настроек доступна кнопка ручного сброса.

---

**После переноса сайта на другой сервер капча не работает.**

При смене сервера `AUTH_KEY` в `wp-config.php` изменился — сохранённые ключи
нельзя расшифровать. Введите ключи заново в **Настройки → SmartCaptcha**.

---

**Firefox показывает предупреждения о трекинге.**

Это Яндекс.Метрика, не капча. SmartCaptcha использует домен
`smartcaptcha.yandexcloud.net`, который не входит в списки трекеров Firefox.
Предупреждения о `mc.yandex.ru` — от кода Яндекс.Метрики на сайте.

---

**Можно ли увеличить лимит запросов?**

Перейдите на платный тариф в Яндекс Cloud, затем измените значение
«Лимит запросов / месяц» в настройках плагина.

---

**Как проверить, что капча реально работает?**

1. Откройте форму в браузере
2. Откройте DevTools → Network
3. Отправьте форму
4. В логах должен появиться запрос к `smartcaptcha.yandexcloud.net/validate`
5. В PHP-логах: `[YSC]` записи покажут результат проверки

## Известные ограничения

**React ошибки #418 и #423** в консоли браузера — внутренние ошибки SmartCaptcha
от Яндекса, не влияют на работу. Исправление зависит от Яндекса.

**`[Violation] unload is not allowed`** — генерируется Яндекс.Метрикой,
не плагином капчи. Браузеры ограничивают `window.onunload` для Back/Forward Cache.

**Яндекс.Метрика заблокирована в Firefox** — расширения приватности и встроенная
защита Firefox блокируют `mc.yandex.ru`. Это поведение браузера пользователя.

**`robustness level` предупреждение** — исправлено в v1.1.0 добавлением
`robustness: 'auto'` в конфигурацию виджета.

## Журнал изменений

### 1.1.3
- Инициализация констант `YSC_CLIENT_KEY`, `YSC_SERVER_KEY`, `YSC_MONTHLY_LIMIT`
  перенесена в хук `plugins_loaded` — устраняет фатальные ошибки при активации
  на некоторых конфигурациях WordPress

### 1.1.2
- **Критическое исправление** `crypto.php`: длина ключа AES-256 была 16 байт
  вместо 32 из-за `substr(hash(...), 0, 32)` на hex-строке.
  Исправлено: `hex2bin(substr(hash(...), 0, 64))`
- **Исправление** `counter.php`: статический кэш не сбрасывался после инкремента.
  Добавлен параметр `$reset_cache = true`
- **Исправление** `notifications.php`: условие `===` для 80% порога пропускало
  уведомление если счётчик перескакивал точное значение. Заменено на `>=`
- **Исправление** `form-patch.php`: фильтры `the_content` и `widget_text`
  игнорировали чекбоксы настроек. Добавлена проверка `$any_enabled`

### 1.1.0
- Шифрование API-ключей (AES-256-CBC) — ключи больше не хранятся в открытом виде
- Страница настроек с чекбоксами управления типами форм
- Добавлена серверная валидация для Contact Form 7
- Динамическая генерация JS-селекторов по настройкам
- Параметр `robustness: 'auto'` в конфигурации виджета
- CSS подключается через `wp_enqueue_style`

### 1.0.0
- Первый релиз
- Поддержка CF7, Impreza, WooCommerce, wp-login.php
- Счётчик запросов с email-уведомлениями
- Виджет на дашборде WordPress
